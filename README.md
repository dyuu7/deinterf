In aeromagnetic exploration, magnetic anomaly target detection, and magnetic navigation, measurements of the external magnetic field are inevitably affected by magnetic interference generated by the aircraft itself. Permanent and induced magnetization of the airframe, eddy currents associated with aircraft maneuvers, and onboard electrical currents all produce additional magnetic fields, which are superimposed on the ambient field measured by the sensor. To mitigate these effects, `deinterf` provides an extensible framework for modeling and compensating aircraft magnetic interference, enabling the platform-induced components to be estimated, separated, and removed from magnetic measurements.

Built on the Tolles–Lawson (T–L) model, `deinterf` represents the compensation problem through composable model terms and [`dataioc`](https://github.com/dyuu7/dataioc)-based data containers that organize and resolve dependencies among the required variables. On top of this modeling framework, it provides a scikit-learn-style `fit`/`predict`/`transform` API, allowing interference models to be constructed, calibrated, and applied in a consistent workflow.

## From a calibration flight to survey compensation

Suppose you have synchronized fluxgate and scalar-magnetometer measurements.
Fit the aircraft interference model on a calibration line, then apply it to
another line recorded with the same sensor configuration.

This example reads public flight `1002` through
[`dafmit-aeromag`](https://github.com/dyuu7/dafmit-aeromag): calibration line
`1002.02` is used for fitting and Renfrew repeat line `158.00` for compensation,
both at 10 Hz. `flux_b_x/y/z` are the three fluxgate components;
`mag_3_uc` is the uncompensated scalar field. All four columns are in nT.

```python
from dafmit_aeromag import Dataset, Selection
from dataioc import DataIoC

from deinterf.compensator.tmi.linear import Terms, TollesLawson
from deinterf.foundation.sensors import MagVector, Tmi
from deinterf.metrics.fom import improve_rate


dataset = Dataset()
columns = ["flux_b_x", "flux_b_y", "flux_b_z", "mag_3_uc"]
calibration = dataset.read(
    Selection(1002, lines="1002.02"), columns=columns, split="train"
)
survey = dataset.read(Selection(1002, lines="158.00"), columns=columns, split="train")


def as_inputs(frame):
    X = DataIoC().with_data(
        MagVector(frame["flux_b_x"], frame["flux_b_y"], frame["flux_b_z"])
    )
    return X, Tmi(frame["mag_3_uc"])


calibration_X, calibration_y = as_inputs(calibration)
survey_X, survey_y = as_inputs(survey)

model = TollesLawson(terms=Terms.Terms_16, sampling_rate=10)
model.fit(calibration_X, calibration_y)
tmi_clean = model.transform(survey_X, survey_y)
print(f"improvement_rate={improve_rate(survey_y, tmi_clean, sampling_rate=10):.2f}")
```

`tmi_clean` contains the compensated survey TMI; `model.predict(survey_X)`
returns the estimated interference. Compensation preserves the input mean and
units. The model defaults to feature standardization, ridge regression, and
0.1–0.6 Hz band-pass filtering during fitting. Set `filter=None` to disable
filtering or pass an `estimator` with `fit` and `predict` methods to use another
regressor.

The reader may download and cache the flight file on first use. Its
`split="train"` selects the released data partition; only the samples passed to
`model.fit` train the compensator. With your own data, replace the two reads and
adapt `as_inputs`: vectors have shape `(n_samples, 3)` and TMI has shape
`(n_samples,)`. Align samples, use uniform sampling, and keep units, axes, and
sampling rate consistent between calibration and survey data.

The complete [classical compensation script](examples/classic_tmi.py) also
plots the before/after signals. From a checkout:

```shell
uv run --extra examples python examples/classic_tmi.py
```

## Concepts at a glance

| Concept | Role in compensation | In this library |
| --- | --- | --- |
| Scalar total field (TMI) | The measured signal to compensate; it contains both the field of interest and aircraft interference | `Tmi`, supplied as `y` |
| Magnetic vector | Three components used to derive field direction and magnitude for modeling | `MagVector`, registered in `DataIoC` |
| Direction cosines | Unitless x/y/z components describing the field direction in the sensor frame | `DirectionalCosine`, derived from `MagVector` by default |
| Calibration maneuvers | Changes in attitude that help estimate interference coefficients; `y` is the measured TMI, not a known clean target | `fit(calibration_X, calibration_y)` |
| T–L terms | Permanent, induced, and eddy-current contributions, linear in their fitted coefficients | `Terms.Terms_16` combines 3 + 5 + 8 features |
| Compensation | Subtract the fitted interference estimate from the measurements on another line | `transform(survey_X, survey_y)` |

Permanent terms describe fixed aircraft magnetization, induced terms describe
magnetization caused by the external field, and eddy-current terms describe
effects of the changing field as the aircraft maneuvers.

`noise_level(y)` computes the standard deviation after 0.1–0.6 Hz band-pass
filtering. `improve_rate(before, after)` divides the former noise level by the
latter; values above one indicate reduced variation in this band. Both default
to 10 Hz, so pass the actual `sampling_rate` when it differs. These figure-of-merit
(FOM) metrics
are useful on calibration maneuvers; on survey lines the band can also contain
geological signal. Evaluate on independent data and interpret the ratio
alongside the survey's geophysical checks.

## Mapping your application to the model

Separate what you measure, what you derive, and how each interference mechanism
contributes features. `DataIoC` resolves the dependencies when the compensator
requests its model terms.

| Application element | Library representation | Example |
| --- | --- | --- |
| A measured input | A data type registered in `DataIoC` | `MagVector`, a custom `Current` |
| A derived physical quantity | A data type with `__build__` | `DirectionalCosine` from `MagVector` |
| An interference mechanism | A `ComposableTerm` returning `(n_samples, n_features)` | Permanent magnetization or cable-current terms |
| The full feature model | Terms combined with `\|` | `Terms.Terms_16 \| CableCurrent()` |
| Fitting and compensation | `TollesLawson` with the chosen terms and regressor | The same `fit` and `transform` workflow |

### Select a sensor source

When you have multiple fluxgates, register each with a distinct index and select
the one used to build features. For example, label the fluxgate from the earlier
example as source `1`:

```python
sensor_X = DataIoC().with_data(MagVector[1](*calibration_X[MagVector].T))
sensor_model = TollesLawson(terms=Terms.Terms_16[1], sampling_rate=10)
sensor_model.fit(sensor_X, calibration_y)
```

Use the same index for the corresponding sensor on survey data. This index
selects a data source, not a feature column. You can also choose
`Terms.Permanent`, `Terms.Induced_5`, or `Terms.Eddy_8`, combine them with `|`,
or select `Terms.Terms_18` for the 3 + 6 + 9 formulation.

### Add a measured interference source

Suppose you record an onboard current and model its field as proportional to
that current along a fixed direction in the sensor frame. Multiplying current
by each direction cosine gives three feature columns whose coefficients are
fitted alongside the T–L terms. Continuing with the calibration data above:

```python
from dataioc import DataNDArray

from deinterf.foundation import ComposableTerm
from deinterf.foundation.sensors import DirectionalCosine


class Current(DataNDArray):
    pass


class CableCurrent(ComposableTerm):
    def __build__(self, container: DataIoC):
        current = container[Current]
        direction = container[DirectionalCosine]
        return current[:, None] * direction


current_data = dataset.read(
    Selection(1002, lines="1002.02"), columns=["cur_com_1"], split="train"
)
current_X = DataIoC().with_data(
    calibration_X[MagVector], Current(current_data["cur_com_1"])
)
current_model = TollesLawson(terms=Terms.Terms_16 | CableCurrent(), sampling_rate=10)
current_model.fit(current_X, calibration_y)
```

`Current` represents the measurement; `CableCurrent` describes how it enters
the model. `DirectionalCosine` is derived automatically from the registered
`MagVector`. To compensate survey data with this model, supply its synchronized
current measurements as well. See the
[cable-current example](examples/extended_cable_current_tmi.py) for multiple
current channels and derivative terms, or the
[load-vibration example](examples/extended_load_vibration_tmi.py) for higher-order
features.

### Derive field direction from INS

If you want direction cosines from an inertial navigation system (INS), combine
position and time with a geomagnetic model, then use attitude to rotate the
field into the sensor frame. Implement that calculation as an
`InsDirectionalCosine` provider and register it with
`container.add_provider(DirectionalCosine, InsDirectionalCosine)`. Existing
T–L terms then consume the replacement direction source.

The [INS example](examples/replace_direction_cosine_source_tmi.py) implements
this chain using IGRF and attitude measurements. It replaces the direction
cosines; field magnitude still comes from `MagVector`. Match rotation order,
angle units, and frame conventions to your instruments.

Register inputs and providers before evaluating a container. Computed values
are cached, so create a new `DataIoC` when changing input data or providers.
Parameter and return-value details are available in the
[`TollesLawson`](deinterf/compensator/tmi/linear/tolles_lawson.py),
[sensor](deinterf/foundation/sensors.py), and
[metric](deinterf/metrics/fom.py) docstrings.

## Contributing

Contributions of interference models, sensor sources, examples, tests, and
fixes are welcome. For a new model term, explain the physical assumptions,
required inputs and units, and provide an example or test with known expected
behavior. Keep the English and Chinese READMEs aligned when changing usage.

Use Ruff to format and lint Python, and ty to check types. From a checkout:

```shell
uv sync --extra examples --group lint
uv run --no-sync ruff check .
uv run --no-sync ty check
uv run --no-sync pytest
```

Before submitting, format the Python files you changed with
`uv run --no-sync ruff format <files>`. Keep formatting changes scoped to those
files. Tests use synthetic local flight data and do not download public data;
without the `examples` extra, the optional example tests are skipped.
